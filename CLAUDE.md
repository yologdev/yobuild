# CLAUDE.md — yobuild

Guidance for Claude Code in this repository. The vision, design and roadmap are in `docs/`; yoagent's own architecture and conventions are in the yoagent repository's root `CLAUDE.md`.

Layout: one crate, `yobuild`. `src/frontend/` (moved from yoagent's `integrations/yoagent-frontend`, history kept) is `yobuild::frontend`; its browser page and TypeScript plugins stay in `frontend/web/` (embedded by `web.rs`; its `package.json` only marks it ESM) and `frontend/plugins/` (its own npm package); `examples/` and `tests/` are the crate's; the pi and DSH adapters the examples load are copied from the yoagent-rutis crate Cargo.lock resolves (the folder `yoagent_rutis::adapters` names; files read in place, such as `dsh/host-services.json`, come from there) into the gitignored `adapters/` by `scripts/copy-adapters.sh` (a stamp of version, source folder and a checksum of the files: a changed source or a copy edited by hand is copied again), then `npm ci` in `adapters/pi` and `adapters/dsh`. Build and test: `cargo clippy --all-targets`, `YOAGENT_RUTIS_REQUIRE_RUNTIMES=1 cargo test` after `scripts/try-coding-agent.sh --setup-only`; CI sets `RUSTFLAGS=-Dwarnings`.

## Frontend (`src/frontend/`, `yobuild::frontend`)

`publish = false`, no API promise; neither yoagent's core nor yoagent-rutis's API depends on it (its one touch outside: the pi adapter's optional dialogs, below). `Session::new(accept_quit) -> (Session, Driver)`: `Driver::run(agent) -> Agent` owns the agent; the `Driver` holds an `Ending` guard, so however it goes (returns, its task panics or is aborted, or it is dropped unrun) an open run gets `RunEnd{outcome: Error}`, the session is marked closed and every frontend gets `Closed`. `Session` (clone; only handles hold the command sender, so dropping them all ends the driver): `observe()` (attached like `connect()`, as a `Client { tx, observer: true }` in the one `clients` map, so it is never counted by `frontends()`, not even for a moment, and goes when its channel closes: a question with only observers gets its default at once; a held one stays open), `connect()` → `Connection { id, messages }` (own unbounded channel per frontend, `Hello` first, then the replay of `Inner.history` (the last `HISTORY` = 5000 `runStart`/`event`/`runEnd`/`notice` broadcasts, recorded in `Inner::broadcast` under `clients` then `history`, so a late frontend gets each message once; kept across a reset; questions not included — Hello carries the open ones) — then `Closed` at once if the session ended — built under the clients lock, nothing dropped; **lock order is `clients` → `ui`**: never take `clients` (`frontends()`, `broadcast`) while holding `ui`), `send(ClientMessage) -> bool` (false + `warn!` once closed; a `UiResponse` resolves its question only if `UiRequest::accepts` the value — confirm: bool, select: an option or null, input: string or null — else it stays open), `is_closed`, `notice(level, msg)`, crate-private `send_to(id, msg)`, `ask(UiRequest, timeout)` / `ask_keyed(.., key)` (no frontend → `default_answer` at once, logged; else broadcast `UiRequest`, first fitting answer wins; a `Close` guard removes the entry however `ask` ends and broadcasts `UiResolved{id, reason: Answered|TimedOut|Withdrawn}`; a key already in use is not taken over (warned) and the guard removes a key only if it maps to its own id), `ask_later(request)` (= `ask_inner(.., timeout None, hold true)`: kept open with no frontend attached (later ones get it in `Hello`), no timeout; the `Ending` guard clears `pending` under `clients` → `ui`, and `ask_inner` returns the default when `is_closed()` under the `ui` lock, so a held question never outlives the session), `withdraw(key)` (unknown key → remembered 60 s, so a withdrawal that overtakes its question returns the default without showing it), `add_ui_plugin(UiPlugin, module) -> Option<u64>` (the version; empty name → `None`), `remove_ui_plugin(name, Option<version>)`, `ui_plugin_module`. Protocol (`protocol.rs`, tag `type`, camelCase, enums `#[non_exhaustive]`): in `prompt`/`steer`/`followUp`/`abort`/`reset`/`uiResponse`/`quit`; out `hello{running,uiPlugins,uiRequests}`, `runStart{run,prompt}`, `event{run,event}` (text/thinking deltas merged by `Coalesced`, held ≤30 ms), `runEnd{run,outcome: RunOutcome(completed|aborted|rejected|stopped|error),error,stats,totalCostUsd}` (always once per run; no `AgentEnd` → `error` + an error `Notice`; `InputRejected` → `rejected`; Abort/Reset/Quit → `aborted`; a stop marker last (`AGENT_STOPPED_PREFIX`: a limit, loop detection, an extension's `Stop`) → `stopped`, its text the error (web: "stopped early: …"); else the last assistant message), `uiRequest`/`uiResolved{id,reason}`, `notice{level,message}`, `uiPlugins`, `closed`. `UiPlugin.version` is `skip_deserializing` (set by the session). Prompt mid-run → queued; steer/followUp idle → a prompt; steering/follow-ups the loop never read (they arrived after its last look, e.g. while extensions `finish`) become the next run's prompt unless the run was aborted (a reset clears them); `Reset` mid-run aborts, drops the queue and clears history after `finish`. `services::provide(root, &session)`: host services `frontend` (`connect(client)` sync → `client.receive(msg)` per message in order, raced against the disposer / the caller's `Connection::closed`, a failed `receive` disconnects it; `send` async, `Err` once closed; `addUiPlugin(info, module)` sync → disposer removing that version only, `Err` on an empty name) and `ui` (`frontends()` sync → the attached count; `request(request, timeoutMs?)` → `Value::future`; `key` must be a string, `timeoutMs` null or a finite non-negative number (fractions ok); `withdraw(key)` string only); unit tests drive `invoke` directly. `web::serve(session, addr) -> Served` (private fields; `url()`, `addr()`, `token()`, `stop()`; dropping it stops serving) (axum 0.8, `ws`): `/`, `/app.js`, `/lib.js` (embedded `frontend/web/`), `/favicon.ico` 204, `/ui-plugins/{name}` (`.js`), `/ws` **requires `?t=<token>`** (uuid v4; 403 otherwise — WebSockets skip CORS, so without it any page could drive the agent); a frame that is not the protocol → `warn!` + a `Notice` to that frontend; UI plugin modules are trusted code. Page: `frontend/web/lib.js` (no DOM; `frontend/web/package.json` marks it as ESM — the terminal UI imports it, and rutis's loader would read it as CommonJS: `toolView(details)` (only the six card kinds), `viewTitle`, `diffRows` (LCS; unaligned when old × new line counts exceed 400²), `parseAnswer(request, text)` (the terminal UI's typed answers: `{value}` or `{error}` → asked again, never guessed), `safeUrl` (http(s)), `markdownParts` (https links only), `Questions` FIFO, `runEndLine`), tested by `node --test frontend/web/lib.test.js`; questions are a docked, non-modal `<dialog>` (`show()`, fixed above the composer, `body.asking` pads the log, "1 of N questions waiting") — the page stays usable while one waits; `app.js` handles messages serially (a promise chain), refuses to send on a closed socket or ended session (says so; the prompt stays in the box, a dialog stays open). `host::PluginHost::builder().node(name, dir).share(svc).terminal(name)?.env(runtime, k, v)?.start(root)` (`env`: added to a runtime process's inherited environment; an entry for a runtime not started fails `start`; `host::DshHome::new()` = `YOAGENT_DSH_HOME` (non-empty; an empty one would mean `~/.dsh` to DSH) else a private 0700 temp dir removed on drop, `env()` = `DSH_HOME` (+ `DSH_AGENTS_HOME` inside a private one); `host::rows_from_file(path, runtime)` reads row lists such as yoagent-rutis's `plugins/dsh/host-services.json`; `coding_agent` / `handoff_agent` load those only with `--dsh-services` — their own DSH plugins need none of them; tests: host_test `env_reaches_only_its_runtime_and_an_unknown_one_is_an_error`, unit tests for `rows_from_file` and `DshHome`) (`terminal(name)`: that runtime inherits stdin and so stays in the terminal's process group — rutis 0.9 puts every other runtime in a group of its own, where touching the terminal stops it (SIGTTIN/SIGTTOU); `coding_agent` sets it for `ui` in terminal mode, `terminal-ui.ts` reads `process.stdin` when it is a TTY, else `/dev/tty`; CI drives the real terminal mode with `tests/terminal_pty.py` (pty: the screen draws, a typed prompt runs a tool, pi's approval question for `rm -rf build` reaches the terminal UI and is answered Block from the keyboard (`bash ✗`), no process stopped meanwhile, the agent still alive), which the headless `--demo` cannot catch) → `load(rows)` (`Row::new(id, name).runtime(r).config(..).inject(..)`; a `Routed` resolver sends a row to its named runtime, others to the first that resolves; a name already routed to another runtime is refused) waits until rows are `Active` (reconcile counts `Pending` as settled), errors naming those that are not; a failed batch is dropped (rows and routes restored; a failed rollback is logged); `status()`; `unload(id)` (row dropped, its route too when no other row loads that name, reconcile; restored on failure) and `reload(id)` = `RuntimeResolver::invalidate(name)` on every runtime's resolver (kept in `PluginHost.runtimes`) + `Loader::reload(id)` (re-describe → the runner's `fresh()` imports the changed file with a `?rutis-reload=<mtime-size>` query → row replaced) + wait until it runs. **Not atomic:** a module that fails to import/describe is refused before anything stops (old version keeps running), but one that fails in `apply` has already replaced the old row, and the loader's rollback re-imports the same (new) file — the plugin stays `Failed` until a later reload succeeds; the error says "running version stays" or "is stopped" (by `is_running(id)`); the example runs `.require_policy()` so a stopped pi policy denies calls. `load` waits only for the rows it added and fails only on `new_failures`, `unload` waits for none — a stopped plugin does not block other changes. **Without `invalidate`, `Loader::reload` is a no-op** for a Node file row (the resolver caches by package version, and a lone file has none) and `Loader::restart` re-applies the already-imported module. Only the plugin's own module is re-imported (not its imports); a `.ts` plugin must sit in a `"type": "module"` package (tsx loads it as CommonJS otherwise, whose cache ignores the query); pi extensions reload with the pi adapter (pi's jiti loader, `moduleCache: false`). `tests/host_test.rs` (temp ESM `.ts` plugin with a `version` tool: edit → new code, unchanged reload restarts, a syntax error refused with the old code kept, an `apply` that throws leaves it stopped (and another plugin still loads), the next good save brings it back, unload removes the tool). **A TS row is Active before its async `apply` finishes** — wait for the handlers you depend on. **A row-level `inject` makes the row wait for every name** (on rutis 0.7/0.8 it stopped a TS row from ever applying; 0.9 applies it — rechecked 2026-10-12); for a service a plugin may go without, re-provide it instead, as `host-ui.ts` does. Plugins (`frontend/plugins/`, own `package.json`: rutis 0.9.1, pi-tui 1.1.0): `terminal-ui.ts` (pi-tui on `frontend`; `/dev/tty` keyboard; questions answered in the editor, a stale prefill cleared when its question closes; tried live in Chrome: an edited pi extension's new question text, a broken save refused); waits for `pi-extensions`/`dsh-tools` handlers; `tracing-subscriber` (stderr with `--web`/`--demo`, else `$TMPDIR/yoagent-coding-agent.log`); a shutdown error never hides the run's. ## Manifest (`src/manifest.rs`, `yobuild::manifest`)

`Manifest::load(path)` (its folder made absolute, `.` components removed) / `parse(text, path, dir)` → `Manifest { dir, agent: Agent { name, model, prompt }, limits, plugins: Vec<Plugin { name, kind: PluginKind::{Pi(Source), Dsh(Source), Rutis { path, runtime }}, config: Option<Map> }>, mcp: Vec<Mcp { name, transport: Transport::{Stdio { source, bin, args, env }, Http { url, headers }} }>, parts: Parts { ask_owner, report: Option<Report>, facts, gate: Gate::{AllowList, Off}, scratch }, dsh, frontend }` (all `#[non_exhaustive]`, as are `Source`, `Runtime`, `ManifestError`), or `ManifestError { path, at: Option<(line, col)>, message }` (Display `path:line:col: message`; columns in characters; a file that cannot be read has no place). Reading has no effect on the process (no `prices::enable_bundled()`: the budget's price is `config().with_prices(&PriceTable::builtin())`). TOML (`toml` 0.8) into `Raw*` structs with `deny_unknown_fields` and `Spanned` where a later check needs a place (tables too), then checked:
- `model = "provider/id"` (id = after the first `/`) → `Model` (private fields; `provider()`, `id()`, `base_url()`, `key_env()`: the variables, first set first, per yoagent 0.25's `resolve_api_key` — `PROVIDERS`: 11, qwen `DASHSCOPE_API_KEY`, google and meta two each; any other provider needs `base_url` (`endpoint`: https, or http on localhost/127.0.0.1/::1, no user; host compared exactly via `url`) + `api_key_env` (an identifier), each refused for a known provider; `LOCAL_PROVIDERS` `ollama` (base_url default `OLLAMA`) and `local` (base_url required) take no key: `api_key_env` refused, `needs_key()` false) → `config()`, `api_key()` / `api_key_with(lookup)`; `yobuild run` must pass the key, an empty one for a local provider (yoagent falls back to `API_KEY` otherwise).
- limits more than 0; `budget_usd` finite and > 0 (yoagent's `Budget::usd` asserts ≥ 0), and priced; the agent's name one plain path component.
- `Source::{Package(Package { name, version }: private, `spec()`), Path}`: npm names (`@scope/name`, lowercase `-._~`, ≤ 214), full semver (no empty pre/build, no leading zeros); git/URL/`file:`/`npm:` specs refused with their own message; paths `./`, `../`, `/` (a rutis plugin's spec is always a path). Names: `name` (letters, digits `-_.`), else the package's name without scope, the file's stem, the URL's host; unique across plugins and servers. `config` a table, dates as text.
- `Value` (private text; `new` checks `${NAME}` references are closed plain names; `references()`, `resolve()` / `resolve_with(lookup)` → `Unset`). One rule, `guard(name, value)`, for a server's env, headers, args (`arguments`: a value named by the flag before it, `--token X`, `--api-key=X`), URL (`server_url`: a `Value`, the endpoint checked with references as `x`, its query parameters by name) and every string of a plugin's config (`check_config`, by its key; filled at start by `Plugin::config_with(lookup)`): a name with a secret's word (`secret()`: split at `_`, `-`, case changes; key, apikey, token, secret, password, passwd, pwd, auth, authorization, cookie, credential(s)) holds only references plus at most `Bearer`/`Basic`/`Token`; a URL in any value has its password as a reference (`written_password`: `://user:password@`).
- `report`: `"handoff"` or a list, through `Report::new` (its errors with the place); `gate` `"allow-list"`/`"off"`; frontend: `phone` needs `web`, not terminal and web both.
Tests: `src/manifest/tests.rs` (every error as the exact `line:col: message`; the full manifest compared field by field; no environment variables set).

## Run (`src/run.rs`, `yobuild::run`; the `yobuild` binary, `src/main.rs`)

`yobuild run <agent.toml> [--scripted FILE] [--once] [--web ADDR] [--] [TASK…]` (hand-parsed; `run --help`; `--` ends options; a blank task is none; `--once` needs one; `--web` only when the frontend is the web page (refused with `--once` or a terminal manifest), a bad address names the option; log via `tracing-subscriber` (`RUST_LOG`, default `warn` minus the registry's mock-key warning; a malformed `RUST_LOG` is said and the default used) to stderr, or `$TMPDIR/yobuild-<agent>-<pid>.log` under the terminal UI; on stderr, in order: the run's error, a shutdown failure or a runtime still running after 10 s, where the log is). `--once` → each tool call (`  name ✓` / `  name ✗ first line`) and notice (`  Info: …`) on stderr, then the last answer and the task's run's outcome (`Completed`, `Stopped: …`, `Error: …`, `Aborted: stopped with Ctrl+C`) on stdout. Exit 1 unless that run (`--once`) or the session's last (web, terminal: `yobuild: the last run ended …`) completed, or none was made. The agent works in the **process's working folder** (yoagent's file tools read relative paths from there; `Options` has no `cwd`, so bash (`with_cwd`), search (`with_root`), the gate, facts and the pi adapter cannot disagree). `run::run(root, Options { manifest, scripted, task, once, addr, layout })` → `Ended { outcome: Option<RunOutcome>, error, notices, agent: Option<Agent> (`None` after Ctrl+C) }`, in three steps:
1. `check` — what can be refused without starting anything: a `once` without a task; the key (`Model::config()`; missing → "provider/id needs its key in VARS"; a local provider gets an empty key; `--scripted` → `run/script.rs`'s `MockProvider`, read strictly, `ModelConfig::mock()`); `prices::enable_bundled()`; the budget (`Budget::for_model`, per run; the manifest refuses an unpriced model, so only a scripted run has none — a note); `Prompt::read` (the file read now; `{scratch}` with `[parts] scratch` off refused; the report's instruction appended; filled with `{cwd}`/`{scratch}` at the start, else "You are <name>, an agent working in <cwd>.", plus " Your scratch folder, for what is not a deliverable: <path>." with a scratch); `run/plugins.rs::plan`; each MCP server's `Launch` (stdio: a path, or an installed package's `bin` via `bin_of` — a string `bin` is named after the package, an object's entry named by `bin` or its only one, a non-path refused; args/env filled; HTTP: URL and headers filled). Notes (`plugin X: its 2 skills are not loaded`, `[dsh] host_services has no effect`, a scripted budget) become Warning notices once the session exists (every frontend gets them: kept in its history; `--once` prints them) and `tracing` info lines.
2. Start — what is refused only once something runs: `Session::new(terminal || once)`, bridge, `services::provide`, a `Scratch` named after the agent when `[parts] scratch`, the `PluginHost` (`ui` + `.terminal("ui")` in terminal mode, `pi`, `dsh` (+ `DshHome` env with host services), `rutis` (Node, in the manifest's folder)), `load` + `wait_for` (the handlers `pi-extensions`/`dsh-tools`; fails at once on `PluginHost::stopped(&[])`, so a runtime that dies while starting is said at once, else names the missing handlers after 60 s), then `dsh_services` when DSH plugins load: `probe_services` loads `adapters/dsh/probe-services.ts` for a moment (`yobuild:dsh-services`; unloaded however it went) to check from inside the runtime that the services their rows inject exist and their modules import — a row missing a service reads `Active` to the host while DSH's loader keeps it waiting. A first look after 1 s, a second after 3 s before a missing service is refused ("DSH plugins wait for services nobody provides: …", hinting `[dsh] host_services = true` and the plugins' unloaded peers); its answer is read strictly (an object, `missing` a list of text, `importErrors` an object; else "the DSH service check answered …"), a probe that fails, loses its runtime, or does not answer within its wait + 15 s is an error naming why. Tools (`Tools`): `tools_in(cwd)` (yoagent's six), `ask_owner` (`AskOwner::TOOL`), each server's (`McpToolAdapter::from_client_with_prefix(server name)`, yoagent 0.25.7: `<server>__<tool>`, the server still called with its own names, so two servers' tools of one name, or one named like a built-in, do not meet; a server with none refused, and one whose prefixed names a model cannot take — `tool_name`: 1 to 64 letters, digits, `_`, `-` — refused: a server's name is checked in `launch` (a default from a URL host has dots: "give the server a `name`"), each tool's once listed (too long only with the prefix → "give the server a shorter `name`")); `Tools::check` refuses two of one name among these and an `ask_owner` from anyone but yobuild. A plugin's tools come with each run (a Node runtime's handler has no static list), so they are not checked here: yoagent keeps one of these over a plugin's of the same name (and logs it), and the gate frees `ask_owner` only when the part adds it. Extensions: bridge, gate (`run::gate`: `AllowList`, with the scratch, `with_free_tools([AskOwner::TOOL])` with the part; plugin and MCP tools ask — no free-tools key yet), report, facts (+ open questions), budget.

## Parts (`src/parts/`, `yobuild::parts`)

Small, generic, no opinion about the task; each plugs into the loop on its own, so it applies to every tool whatever ecosystem it comes from. Tests: `tests/parts_test.rs` (34, through a real `Session` + `Driver` + `MockProvider`; `until_all` collects until every expected message came, in any order — a question is broadcast from its own task), unit tests in `ask_owner.rs`, `report.rs`, `scratch.rs`.

`AskOwner` (tool `ask_owner` = `AskOwner::TOOL`, not freed by the gate by default; one per session, clones share the numbering and the count): `Question::new(question, why, options)` trims, refuses a blank question, drops blank and repeated options; `Question::from_json` refuses wrong shapes (not an object, non-string `why`/options, unknown keys such as `choices`) — the tool and a future host service share it. `ask(Question) -> n` (needs a Tokio runtime): Select with ≥2 options, else Input; returns at once; a spawned task awaits `Session::ask_later` → `Some(answer)` → `ClientMessage::Steer` `[Owner's answer to #N] <question>\n<answer>` / `[Owner skipped #N] <question>` (blank answer); `None` (withdrawn by a reset — `Inner::withdraw_held` drops `UiState.held` questions — or the session ended) → nothing; a steer the closed session refuses is logged. `open_questions()` → `OpenQuestions` (no other way to make one); a drop guard counts a question off however its task ends.

`Report` (extension `report`, **Required**): `Report::new(sections) -> Result` (at least one, trimmed, none blank or repeated); `handoff()` = Done / Waiting on you / Decisions / Next; `instruction()` for the system prompt; `on_stop` (private `ReportRun`) → `Continue("End with the report: sections ## A, ## B. Missing: …")` until every name appears in the last message (case-insensitive, anywhere: lenient on purpose); still missing after yoagent's `max_stop_continues` (3) → the run fails ("not accepted after 3 continues"), seen by the frontends.

`Facts` (extension `facts`): `Facts::new(session, cwd)` does no I/O; the snapshot is taken in the first run's `start_run` (an async mutex; kept for the session, whatever it found): `Snapshot::{NotRepo, Unknown(why), Repo(Start)}` — `Start { root (rev-parse --show-toplevel), head (None = unborn), tree, edits_known, tips (every ref tip + head), untracked (path → size, mtime), taken }`; `tree` = `git stash create` (else `head` when nothing is uncommitted); unborn → `git write-tree` (the staged files), `edits_known` false if `git diff --quiet` shows unstaged edits; a failed `stash create` → `edits_known` false ("(the edits already there could not be told apart)"). Every git call goes through `Git` (`facts.rs`): run at `root`, `LC_ALL=C`/`LANGUAGE=C`, `GIT_OPTIONAL_LOCKS=0`, `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE` from the environment removed, and — `with_index_copy` — `GIT_INDEX_FILE` a private copy of the index in a temp dir, so the owner's index is never written and a git killed at the 4 s limit (`kill_on_drop`) leaves no lock behind. `head()` is `None` only for `rev-parse --verify -q HEAD` exiting 1 with empty stderr; any other failure is an error. Errors kept apart (`GitError::NotRepo` only when git says so, else `Failed`): "not a git repository" (+ " at the start (one was made since)"), "changes unknown: no snapshot at the start (git: …)", "changes since the start unknown (git: …)" — never "no changes" when git cannot tell. `finish` → Info `Facts: since the start: <diff --no-relative --shortstat vs tree, or no changes>, N new commit(s) (rev-list HEAD --not <tips>)[, M commit(s) no longer in HEAD | , HEAD has no commit now][ (…could not be told apart)][, new: a, b | , N new: a, b, c, …][, changed untracked: …][, removed untracked: …] | , new files unknown; T tokens in (input + cache read + cache write), U out; K tool call(s); Ss[; Q question(s) waiting on you].` — "new" files are untracked now, not then, and made after the snapshot (an ignore rule removed does not make old files new); ignored files are not counted; paths are from the repository's top folder. A `RunEnd::Stopped` run also gets a Warning (`Stopped early: <reason>. Send "continue" …`).
