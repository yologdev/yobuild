# CLAUDE.md — yobuild

Guidance for Claude Code in this repository. The vision, design and roadmap are in `docs/`; yoagent's own architecture and conventions are in the yoagent repository's root `CLAUDE.md`.

Layout: one crate, `yobuild`. `src/frontend/` (moved from yoagent's `integrations/yoagent-frontend`, history kept) is `yobuild::frontend`; its browser page and TypeScript plugins stay in `frontend/web/` (embedded by `web.rs`; its `package.json` only marks it ESM) and `frontend/plugins/` (its own npm package); `examples/` and `tests/` are the crate's; the pi and DSH adapters the examples load are vendored in `vendor/yoagent-rutis/plugins/` (`scripts/check-vendor.sh`). Build and test: `cargo clippy --all-targets`, `YOAGENT_RUTIS_REQUIRE_RUNTIMES=1 cargo test` after `scripts/try-coding-agent.sh --setup-only`; CI sets `RUSTFLAGS=-Dwarnings`.

## Frontend (`src/frontend/`, `yobuild::frontend`)

`publish = false`, no API promise; neither yoagent's core nor yoagent-rutis's API depends on it (its one touch outside: the pi adapter's optional dialogs, below). `Session::new(accept_quit) -> (Session, Driver)`: `Driver::run(agent) -> Agent` owns the agent; the `Driver` holds an `Ending` guard, so however it goes (returns, its task panics or is aborted, or it is dropped unrun) an open run gets `RunEnd{outcome: Error}`, the session is marked closed and every frontend gets `Closed`. `Session` (clone; only handles hold the command sender, so dropping them all ends the driver): `connect()` → `Connection { id, messages }` (own unbounded channel per frontend, `Hello` first, then the replay of `Inner.history` (the last `HISTORY` = 5000 `runStart`/`event`/`runEnd`/`notice` broadcasts, recorded in `Inner::broadcast` under `clients` then `history`, so a late frontend gets each message once; kept across a reset; questions not included — Hello carries the open ones) — then `Closed` at once if the session ended — built under the clients lock, nothing dropped; **lock order is `clients` → `ui`**: never take `clients` (`frontends()`, `broadcast`) while holding `ui`), `send(ClientMessage) -> bool` (false + `warn!` once closed; a `UiResponse` resolves its question only if `UiRequest::accepts` the value — confirm: bool, select: an option or null, input: string or null — else it stays open), `is_closed`, `notice(level, msg)`, crate-private `send_to(id, msg)`, `ask(UiRequest, timeout)` / `ask_keyed(.., key)` (no frontend → `default_answer` at once, logged; else broadcast `UiRequest`, first fitting answer wins; a `Close` guard removes the entry however `ask` ends and broadcasts `UiResolved{id, reason: Answered|TimedOut|Withdrawn}`; a key already in use is not taken over (warned) and the guard removes a key only if it maps to its own id), `ask_later(request)` (= `ask_inner(.., timeout None, hold true)`: kept open with no frontend attached (later ones get it in `Hello`), no timeout; the `Ending` guard clears `pending` under `clients` → `ui`, and `ask_inner` returns the default when `is_closed()` under the `ui` lock, so a held question never outlives the session), `withdraw(key)` (unknown key → remembered 60 s, so a withdrawal that overtakes its question returns the default without showing it), `add_ui_plugin(UiPlugin, module) -> Option<u64>` (the version; empty name → `None`), `remove_ui_plugin(name, Option<version>)`, `ui_plugin_module`. Protocol (`protocol.rs`, tag `type`, camelCase, enums `#[non_exhaustive]`): in `prompt`/`steer`/`followUp`/`abort`/`reset`/`uiResponse`/`quit`; out `hello{running,uiPlugins,uiRequests}`, `runStart{run,prompt}`, `event{run,event}` (text/thinking deltas merged by `Coalesced`, held ≤30 ms), `runEnd{run,outcome: RunOutcome(completed|aborted|rejected|error),error,stats,totalCostUsd}` (always once per run; no `AgentEnd` → `error` + an error `Notice`; `InputRejected` → `rejected`; Abort/Reset/Quit → `aborted`; else the last assistant message), `uiRequest`/`uiResolved{id,reason}`, `notice{level,message}`, `uiPlugins`, `closed`. `UiPlugin.version` is `skip_deserializing` (set by the session). Prompt mid-run → queued; steer/followUp idle → a prompt; steering/follow-ups the loop never read (they arrived after its last look, e.g. while extensions `finish`) become the next run's prompt unless the run was aborted (a reset clears them); `Reset` mid-run aborts, drops the queue and clears history after `finish`. `services::provide(root, &session)`: host services `frontend` (`connect(client)` sync → `client.receive(msg)` per message in order, raced against the disposer / the caller's `Connection::closed`, a failed `receive` disconnects it; `send` async, `Err` once closed; `addUiPlugin(info, module)` sync → disposer removing that version only, `Err` on an empty name) and `ui` (`frontends()` sync → the attached count; `request(request, timeoutMs?)` → `Value::future`; `key` must be a string, `timeoutMs` null or a finite non-negative number (fractions ok); `withdraw(key)` string only); unit tests drive `invoke` directly. `web::serve(session, addr) -> Served` (private fields; `url()`, `addr()`, `token()`, `stop()`; dropping it stops serving) (axum 0.8, `ws`): `/`, `/app.js`, `/lib.js` (embedded `frontend/web/`), `/favicon.ico` 204, `/ui-plugins/{name}` (`.js`), `/ws` **requires `?t=<token>`** (uuid v4; 403 otherwise — WebSockets skip CORS, so without it any page could drive the agent); a frame that is not the protocol → `warn!` + a `Notice` to that frontend; UI plugin modules are trusted code. Page: `frontend/web/lib.js` (no DOM; `frontend/web/package.json` marks it as ESM — the terminal UI imports it, and rutis's loader would read it as CommonJS: `toolView(details)` (only the six card kinds), `viewTitle`, `diffRows` (LCS; unaligned when old × new line counts exceed 400²), `parseAnswer(request, text)` (the terminal UI's typed answers: `{value}` or `{error}` → asked again, never guessed), `safeUrl` (http(s)), `markdownParts` (https links only), `Questions` FIFO, `runEndLine`), tested by `node --test frontend/web/lib.test.js`; questions are a docked, non-modal `<dialog>` (`show()`, fixed above the composer, `body.asking` pads the log, "1 of N questions waiting") — the page stays usable while one waits; `app.js` handles messages serially (a promise chain), refuses to send on a closed socket or ended session (says so; the prompt stays in the box, a dialog stays open). `host::PluginHost::builder().node(name, dir).share(svc).terminal(name)?.env(runtime, k, v)?.start(root)` (`env`: added to a runtime process's inherited environment; an entry for a runtime not started fails `start`; `host::DshHome::new()` = `YOAGENT_DSH_HOME` (non-empty; an empty one would mean `~/.dsh` to DSH) else a private 0700 temp dir removed on drop, `env()` = `DSH_HOME` (+ `DSH_AGENTS_HOME` inside a private one); `host::rows_from_file(path, runtime)` reads row lists such as yoagent-rutis's `plugins/dsh/host-services.json`; `coding_agent` / `handoff_agent` load those only with `--dsh-services` — their own DSH plugins need none of them; tests: host_test `env_reaches_only_its_runtime_and_an_unknown_one_is_an_error`, unit tests for `rows_from_file` and `DshHome`) (`terminal(name)`: that runtime inherits stdin and so stays in the terminal's process group — rutis 0.9 puts every other runtime in a group of its own, where touching the terminal stops it (SIGTTIN/SIGTTOU); `coding_agent` sets it for `ui` in terminal mode, `terminal-ui.ts` reads `process.stdin` when it is a TTY, else `/dev/tty`; CI drives the real terminal mode with `tests/terminal_pty.py` (pty: the screen draws, a typed prompt runs a tool, pi's approval question for `rm -rf build` reaches the terminal UI and is answered Block from the keyboard (`bash ✗`), no process stopped meanwhile, the agent still alive), which the headless `--demo` cannot catch) → `load(rows)` (`Row::new(id, name).runtime(r).config(..).inject(..)`; a `Routed` resolver sends a row to its named runtime, others to the first that resolves; a name already routed to another runtime is refused) waits until rows are `Active` (reconcile counts `Pending` as settled), errors naming those that are not; a failed batch is dropped (rows and routes restored; a failed rollback is logged); `status()`; `unload(id)` (row dropped, its route too when no other row loads that name, reconcile; restored on failure) and `reload(id)` = `RuntimeResolver::invalidate(name)` on every runtime's resolver (kept in `PluginHost.runtimes`) + `Loader::reload(id)` (re-describe → the runner's `fresh()` imports the changed file with a `?rutis-reload=<mtime-size>` query → row replaced) + wait until it runs. **Not atomic:** a module that fails to import/describe is refused before anything stops (old version keeps running), but one that fails in `apply` has already replaced the old row, and the loader's rollback re-imports the same (new) file — the plugin stays `Failed` until a later reload succeeds; the error says "running version stays" or "is stopped" (by `is_running(id)`); the example runs `.require_policy()` so a stopped pi policy denies calls. `load` waits only for the rows it added and fails only on `new_failures`, `unload` waits for none — a stopped plugin does not block other changes. **Without `invalidate`, `Loader::reload` is a no-op** for a Node file row (the resolver caches by package version, and a lone file has none) and `Loader::restart` re-applies the already-imported module. Only the plugin's own module is re-imported (not its imports); a `.ts` plugin must sit in a `"type": "module"` package (tsx loads it as CommonJS otherwise, whose cache ignores the query); pi extensions reload with the pi adapter (pi's jiti loader, `moduleCache: false`). `tests/host_test.rs` (temp ESM `.ts` plugin with a `version` tool: edit → new code, unchanged reload restarts, a syntax error refused with the old code kept, an `apply` that throws leaves it stopped (and another plugin still loads), the next good save brings it back, unload removes the tool). **A TS row is Active before its async `apply` finishes** — wait for the handlers you depend on. **A row-level `inject` makes the row wait for every name** (on rutis 0.7/0.8 it stopped a TS row from ever applying; 0.9 applies it — rechecked 2026-10-12); for a service a plugin may go without, re-provide it instead, as `host-ui.ts` does. Plugins (`frontend/plugins/`, own `package.json`: rutis 0.9.1, pi-tui 1.1.0): `terminal-ui.ts` (pi-tui on `frontend`; `/dev/tty` keyboard; questions answered in the editor, a stale prefill cleared when its question closes; `receive` never throws (shown instead); a failed quit goes to stderr; `demo` headless prints `[header, log, status]` and declines questions), `search-links.ts` (UI plugin: `renderTool` links for search tools, `mountPanel` quick prompts), `pi-extensions/confirm-dangerous.ts` (a pi permission gate using `ctx.ui.select`). pi dialogs: rutis shows a **host** service only to plugins that inject it and starts a plugin only once all injected services exist, so `vendor/yoagent-rutis/plugins/pi/host-ui.ts` injects `ui` and re-provides it in the pi runtime as `pi-host-ui`; the adapter looks that up per pi context (`lookupUi`; missing → print mode, said once at debug) → RPC mode (`mode: 'rpc'`, `hasUI: true`, `select`/`confirm`/`input`/`editor`/`notify` forwarded; failures → print-mode answers); each question keyed `pi-<randomUUID>` and withdrawn on its signal's abort (a failed withdraw is reported at warn); without it, print mode unchanged. `examples/minimal_browser.rs`: the smallest use — `Session::new(false)` + `web::serve` + an agent with read-only tools (`list_files`, `read_file`, `search`) sandboxed to the cwd (`with_allowed_paths`; the built-ins allow every path by default), no plugins or Node; scripted, or `--live` DeepSeek; tried live in Chrome. `examples/coding_agent.rs`: runtimes `ui`/`pi`/`dsh`, terminal (default) or `--web [ADDR]` (8787), `--demo`, `--live` (`DEEPSEEK_API_KEY`), `--no-dsh`, `--watch` (a task owning the `PluginHost` polls the plugin files every 500 ms by mtime + size — row files, the pi extension → `pi`, terminal-ui in terminal mode — settles 200 ms (files changed meanwhile are reloaded too), `reload`s the owning row and sends every frontend a `Notice` — Info, Warning when the old version stays, Error when the plugin is stopped; tried live in Chrome: an edited pi extension's new question text, a broken save refused); waits for `pi-extensions`/`dsh-tools` handlers; `tracing-subscriber` (stderr with `--web`/`--demo`, else `$TMPDIR/yoagent-coding-agent.log`); a shutdown error never hides the run's. Tool cards: a result's `details.view` (DSH's card vocabulary) is drawn by `app.js` `card()` (terminal/diff/search/read/web/generic; `CARD_LINES` 200 per block, ≤20 web sources; a generic card with no text draws nothing; a card that throws → "(this tool's card could not be drawn)") unless a UI plugin draws that tool; the line takes `viewTitle` (browser: only then; terminal UI: always). `UiRequest::Select { title, message, options, multiple }` (answer: a list of distinct options with `multiple`; a frontend that cannot offer several must leave it unanswered), `Input` has `message` too; `ask_keyed` asks `request.normalized()` (a select's options each once). ## Parts (`src/parts/`, `yobuild::parts`)

Small, generic, no opinion about the task; each plugs into the loop on its own, so it applies to every tool whatever ecosystem it comes from. Tests: `tests/parts_test.rs` (17, through a real `Session` + `Driver` + `MockProvider`; `until_all` collects until every expected message came, in any order — a question is broadcast from its own task), unit tests in `ask_owner.rs`, `report.rs`, `scratch.rs`.

`AskOwner` (tool `ask_owner`; one per session, clones share the numbering and the count): `Question::new(question, why, options)` trims, refuses a blank question, drops blank and repeated options; `Question::from_json` refuses wrong shapes (non-string `why`/options) — the tool and a future host service share it. `ask(Question) -> n` (needs a Tokio runtime): Select with ≥2 options, else Input; returns at once; a spawned task awaits `Session::ask_later` → `Some(answer)` → `ClientMessage::Steer` `[Owner's answer to #N] <question>\n<answer>` / `[Owner skipped #N] <question>` (blank answer); `None` (withdrawn by a reset — `Inner::withdraw_held` drops `UiState.held` questions — or the session ended) → nothing; a steer the closed session refuses is logged. `open_questions()` → `OpenQuestions` (no other way to make one); a drop guard counts a question off however its task ends.

`Report` (extension `report`, **Required**): `Report::new(sections) -> Result` (at least one, trimmed, none blank or repeated); `handoff()` = Done / Waiting on you / Decisions / Next; `instruction()` for the system prompt; `on_stop` (private `ReportRun`) → `Continue("End with the report: sections ## A, ## B. Missing: …")` until every name appears in the last message (case-insensitive, anywhere: lenient on purpose); still missing after yoagent's `max_stop_continues` (3) → the run fails ("not accepted after 3 continues"), seen by the frontends.

`Facts` (extension `facts`): `Facts::new(session, cwd)` does no I/O; the snapshot is taken in the first run's `start_run` (`OnceCell`): `Repo { head, tree, edits_known, untracked }` — `tree` = `git stash create` (else `head` when nothing is uncommitted); in a repository with no commit, `git write-tree` (the staged files) with `edits_known` false if `git diff --quiet` shows unstaged edits; a failed snapshot → `edits_known` false (the fact then says "(the edits already there could not be told apart)"). git runs as `tokio::process` (`kill_on_drop`), each snapshot and each run's facts within 4 s (`GIT_TIME`; yoagent gives `finish` 5 s). Errors kept apart (`Git::NotRepo` only when git says so, else `Failed`): "not a git repository"; "changes unknown (git: …)" (git missing, failed or timed out at the start); "changes since the start unknown (git: …)" (a diff or count failed later) — never "no changes" when git cannot tell; "new files unknown" when either untracked list failed (`ls-files -z`). `finish` → Info `Facts: since the start: <shortstat or no changes>, N commit(s)[ (…could not be told apart)][, new: a, b | , N new files: a, b, c, … | , new files unknown]; T tokens in (input + cache read + cache write), U out; K tool call(s); Ss[; Q question(s) waiting on you].` (counts per run; the clause only `with_open_questions`); a `RunEnd::Stopped` run also gets a Warning (`Stopped early: <reason>. Send "continue" …`).

`Scratch`: `create(name)` = a new empty `<temp>/<name>-<random>` (`tempfile`, kept), `name` one plain path component; `at(path)` creates if missing, absolute (canonicalized); errors name the path; left in place at the end; `ENV` = `YOBUILD_SCRATCH` (what `confirm-dangerous.ts` reads).
