# CLAUDE.md — yobuild

Guidance for Claude Code in this repository. The vision, design and roadmap are in `docs/`; yoagent's own architecture and conventions are in the yoagent repository's root `CLAUDE.md`.

Layout: one crate, `yobuild`. `src/frontend/` (moved from yoagent's `integrations/yoagent-frontend`, history kept) is `yobuild::frontend`; its browser page and TypeScript plugins stay in `frontend/web/` (embedded by `web.rs`; its `package.json` only marks it ESM) and `frontend/plugins/` (its own npm package); `examples/` and `tests/` are the crate's; the pi and DSH adapters the examples load are copied from the yoagent-rutis crate Cargo.lock resolves (the folder `yoagent_rutis::adapters` names; files read in place, such as `dsh/host-services.json`, come from there) into the gitignored `adapters/` by `scripts/copy-adapters.sh` (a stamp of version, source folder and a checksum of the files: a changed source or a copy edited by hand is copied again), then `npm ci` in `adapters/pi` and `adapters/dsh`. Build and test: `cargo clippy --all-targets`, `YOAGENT_RUTIS_REQUIRE_RUNTIMES=1 cargo test` after `scripts/try-coding-agent.sh --setup-only`; CI sets `RUSTFLAGS=-Dwarnings`.

## Frontend (`src/frontend/`, `yobuild::frontend`)

`publish = false`, no API promise; neither yoagent's core nor yoagent-rutis's API depends on it (its one touch outside: the pi adapter's optional dialogs, below). `Session::new(accept_quit) -> (Session, Driver)`: `Driver::run(agent) -> Agent` owns the agent; the `Driver` holds an `Ending` guard, so however it goes (returns, its task panics or is aborted, or it is dropped unrun) an open run gets `RunEnd{outcome: Error}`, the session is marked closed and every frontend gets `Closed`. `Session` (clone; only handles hold the command sender, so dropping them all ends the driver): `observe()` (attached like `connect()`, as a `Client { tx, observer: true }` in the one `clients` map, so it is never counted by `frontends()`, not even for a moment, and goes when its channel closes: a question with only observers gets its default at once; a held one stays open), `connect()` → `Connection { id, messages }` (own unbounded channel per frontend, `Hello` first, then the replay of `Inner.history` (the last `HISTORY` = 5000 `runStart`/`event`/`runEnd`/`notice` broadcasts, recorded in `Inner::broadcast` under `clients` then `history`, so a late frontend gets each message once; kept across a reset; questions not included — Hello carries the open ones) — then `Closed` at once if the session ended — built under the clients lock, nothing dropped; **lock order is `clients` → `ui`**: never take `clients` (`frontends()`, `broadcast`) while holding `ui`), `send(ClientMessage) -> bool` (false + `warn!` once closed; a `UiResponse` resolves its question only if `UiRequest::accepts` the value — confirm: bool, select: an option or null, input: string or null — else it stays open), `is_closed`, `id()` (a uuid made once) and `generation()` (bumped by each Reset, first, in `Inner::reset`, the one place both of the driver's reset paths go), `wake(text)` (a plugin's words, tagged by the caller, as a driver `Command::Wake` — never on the wire: the driver reads `Command::{Client, Wake}`): mid-run, steering (remembered as the run's `woke`); idle, a run of its own only once a run has started (`has_started`, the driver's test too) and one of `allow_wakes(n)` is left (`wakes_left`; 0 until set; set once — a second call is ignored, `false`; `run` sets it where it makes the session); a wake the run never read — still queued as it ends, or taken by the loop as it was stopping — counts the same way: a plugin's wake among a completed run's late steering starts the next run only by taking a wake (unless the owner's late steering starts it anyway), and after an abort, reset or failed task (no `AgentEnd`) one not among this run's messages (the prompt aside; multisets, so a repeated text is counted per copy) is dropped, while the owner's steering of the run that was never read — queued, or taken by the stopping loop (yoagent's takes it even then) — is steered again (a reset clears it); each one not delivered is a Warning notice ("A plugin's wake was not delivered (…)"; wakes still in the channel as the driver exits are logged), `notice(level, msg)`, crate-private `send_to(id, msg)`, `ask(UiRequest, timeout)` / `ask_keyed(.., key)` (no frontend → `default_answer` at once, logged; else broadcast `UiRequest`, first fitting answer wins; a `Close` guard removes the entry however `ask` ends and broadcasts `UiResolved{id, reason: Answered|TimedOut|Withdrawn}`; a key already in use is not taken over (warned) and the guard removes a key only if it maps to its own id), `ask_later(request)` (= `ask_inner(.., timeout None, hold true)`: kept open with no frontend attached (later ones get it in `Hello`), no timeout; the `Ending` guard clears `pending` under `clients` → `ui`, and `ask_inner` returns the default when `is_closed()` under the `ui` lock, so a held question never outlives the session), `withdraw(key)` (unknown key → remembered 60 s, so a withdrawal that overtakes its question returns the default without showing it), `add_ui_plugin(UiPlugin, module) -> Option<u64>` (the version; empty name → `None`), `remove_ui_plugin(name, Option<version>)`, `ui_plugin_module`. Protocol (`protocol.rs`, tag `type`, camelCase, enums `#[non_exhaustive]`): in `prompt`/`steer`/`followUp`/`abort`/`reset`/`uiResponse`/`quit`; out `hello{running,uiPlugins,uiRequests}`, `runStart{run,prompt}`, `event{run,event}` (text/thinking deltas merged by `Coalesced`, held ≤30 ms), `runEnd{run,outcome: RunOutcome(completed|aborted|rejected|stopped|error),error,stats,totalCostUsd}` (always once per run; no `AgentEnd` → `error` + an error `Notice`; `InputRejected` → `rejected`; Abort/Reset/Quit → `aborted`; a stop marker last (`AGENT_STOPPED_PREFIX`: a limit, loop detection, an extension's `Stop`) → `stopped`, its text the error (web: "stopped early: …"); else the last assistant message), `uiRequest`/`uiResolved{id,reason}`, `notice{level,message}`, `uiPlugins`, `closed`. `UiPlugin.version` is `skip_deserializing` (set by the session). Prompt mid-run → queued; steer/followUp idle → a prompt; steering/follow-ups the loop never read (they arrived after its last look, e.g. while extensions `finish`) become the next run's prompt unless the run was aborted (a reset clears them); ## Manifest (`src/manifest.rs`, `yobuild::manifest`)

`Manifest::load(path)` (its folder made absolute, `.` components removed) / `parse(text, path, dir)` → `Manifest { path, dir, agent: Agent { name, model, prompt }, limits, plugins: Vec<Plugin { name, kind: PluginKind::{Pi(Source), Dsh(Source), Rutis { path, runtime }}, config: Option<Map>, allow }>, mcp: Vec<Mcp { name, transport: Transport::{Stdio { source, bin, args, env }, Http { url, headers }}, allow }>, builtins: Builtins { ask_owner, report: Option<Report>, facts, gate: Gate::{AllowList, Off}, scratch }, dsh, frontend }` (all `#[non_exhaustive]`, as are `Source`, `Runtime`, `ManifestError`), or `ManifestError { path, at: Option<(line, col)>, message }` (Display `path:line:col: message`; columns in characters; a file that cannot be read has no place). Reading has no effect on the process (no `prices::enable_bundled()`: the budget's price is `config().with_prices(&PriceTable::builtin())`). TOML (`toml` 0.8) into `Raw*` structs with `deny_unknown_fields` and `Spanned` where a later check needs a place (tables too), then checked:
- `model = "provider/id"` (id = after the first `/`) → `Model` (private fields; `config()` is yoagent's preset when one matches provider and id (`PRESETS`: yoagent 0.25.9's 22, each priced: real context window, output limit, protocol), else the provider's generic constructor; `provider()`, `id()`, `base_url()`, `key_env()`: the variables, first set first, per yoagent 0.25's `resolve_api_key` — `PROVIDERS`: 11, qwen `DASHSCOPE_API_KEY`, google and meta two each; any other provider needs `base_url` (`endpoint`: https, or http on localhost/127.0.0.1/::1, no user; host compared exactly via `url`) + `api_key_env` (an identifier), each refused for a known provider; `LOCAL_PROVIDERS` `ollama` (base_url default `OLLAMA`) and `local` (base_url required) take no key: `api_key_env` refused, `needs_key()` false) → `config()`, `api_key()` / `api_key_with(lookup)`; `yobuild run` must pass the key, an empty one for a local provider (yoagent falls back to `API_KEY` otherwise).
- limits more than 0; `budget_usd` finite and > 0 (yoagent's `Budget::usd` asserts ≥ 0), and priced; the agent's name one plain path component.
- `Source::{Package(Package { name, version }: private, `spec()`), Path}`: npm names (`@scope/name`, lowercase `-._~`, ≤ 214), full semver (no empty pre/build, no leading zeros); git/URL/`file:`/`npm:` specs refused with their own message; paths `./`, `../`, `/` (a rutis plugin's spec is always a path). Names: `name` (letters, digits `-_.`), else the package's name without scope, the file's stem, the URL's host; unique across plugins and servers. Within one install set (pi, DSH, stdio MCP), two entries pinning one package at different versions are refused ("x@1.0.1: another entry pins x at 1.0.0, and the `pi` set holds one version of a package", at the second entry). `config` a table, dates as text.
- `Value` (private text; `new` checks `${NAME}` references are closed plain names; `references()`, `resolve()` / `resolve_with(lookup)` → `Unset`). One rule, `guard(name, value)`, for a server's env, headers, args (`arguments`: a value named by the flag before it, `--token X`, `--api-key=X`), URL (`server_url`: a `Value`, the endpoint checked with references as `x`, its query parameters by name) and every string of a plugin's config (`check_config`, by its key; filled at start by `Plugin::config_with(lookup)`): a name with a secret's word (`secret()`: split at `_`, `-`, case changes; key, apikey, token, secret, password, passwd, pwd, auth, authorization, cookie, credential(s)) holds only references plus at most `Bearer`/`Basic`/`Token`; a URL in any value has its password as a reference (`written_password`: `://user:password@`).
- `grants` on a `[[plugin]]` (design §12: what its host gives it; `Grants { workspace, trust, model: Option<ModelGrant::Info>, wake }`, `names()`, all off when absent, `deny_unknown_fields`): read for a rutis plugin; `exec`/`observe` refused ("for a pi extension"), `model` only `"info"`, and any grant on a pi or DSH plugin refused at the table ("… come with yobuild's pi/DSH host (design §12, M3b), not yet").
- `[builtins] tools = "coding" | "read-only"` (`Tools`), `[limits] session_budget_usd` (checked like `budget_usd`), `policy = true` on a `[[plugin]]` (design §7; `require_policy`: while no handler with `before_tool` is up, calls are denied — for all plugins at once; refused on a DSH plugin, whose adapter judges no calls).
- `allow` (design §2, Allowed tools) on a `[[plugin]]` or `[[mcp]]`: the entry's tools, as it names them, the gate lets run without asking; refused when read: a name a tool cannot have (1 to 64 letters, digits, `_`, `-`), a repeat, any non-empty `allow` with `gate = "off"`, and on a plugin `JUDGED_TOOLS` (`bash`, `write_file`, `write`, `edit_file`, `edit`: judged call by call), `ask_owner` (the built-in allows its own) and a name with `__` (an MCP server's tool: only its entry may allow it) — a server's names are its own (`files__bash`); an MCP server's name may not hold `__` (prefixes would be ambiguous). MCP names are scoped: checked against the server's own list, static (yoagent keeps them over a plugin's tool of that name), no duplicates (`Tools::check`). ## Hints (`src/hints.rs`, crate-private; design §11)

One table, `HINTS: [Hint { id, scope, pattern, fix }]`, each hint scoped to where its message is seen — `Scope::Stop` (a run's error when it ended `Stopped`), `Fail` (`Error` or `Rejected`), `Call` (a refused tool call's result; the run goes on), `Start` (`check`'s problems, `run`'s refusals, its "A plugin stopped" Notices) — so a fix is never given for another kind of failure (a server's own `Auth error` in a check problem is not the model's key). Patterns are the messages' fixed parts, matched as written: yoagent's markers included (`[Agent stopped: Max turns reached`, `[Agent stopped: session budget of` before `… budget of`, `[Extension failed: report] …`), the provider's `Auth error: ` and `Rate limited` (only for failed runs), `the run ended unexpectedly: the agent task failed` (`session::TASK_FAILED`), `input rejected: the plugin host is not running`, the bridge's call denials (`no plugin policy is loaded…`, `its plugin unloaded`, `did not answer \`before_tool\` within`, `a required plugin handler failed this run`), and what start and `check` say (DSH services, `nothing provides`, the policy's judge never registered, not registering together, a run stopping at once, `plugins failed to load`, ``stopped: plugin ` ``, a runtime not running, an MCP server with no tools or a wrong `allow`, the terminal UI). `hint(scope, message)`; `what_to_do(stopped, error)` — a stop no hint names is a plugin's: "its reason says why; send \"continue\" only once that cause is gone". Used by `run::what_to_do(outcome, error)` (pub: `Stopped`, `Error`, `Rejected`), `run::what_to_do_at_start(error)` (pub: `Start`); `run`'s watcher sends `What to do: <fix>.` (Info) after such a run and once a run for a refused call it knows (in every mode — its `ToolExecutionEnd` handling no longer only prints); the "A plugin stopped" Notice gets one too; `main.rs` adds `  what to do: …` under `the last run ended …` (not under `--once`, which prints the Notice) and under a refusal; `check`'s `Problem::new` (`Start`). `run::SESSION_BUDGET` names the session budget. Tests: each hint against its message as the code makes it (yoagent's prefixes, `ProviderError`, `TASK_FAILED`, `SESSION_BUDGET`, or the copied format with where it comes from), the precedence and what must match nothing (numbers holding 401, a provider's error in a check problem, a plugin's stop mentioning a budget), `what_to_do` per outcome, unique ids, and `skill/yobuild/reference/failures.md` naming every hint and no other; `run_test` captures real ones (the report's failure, the policy's runtime dying — its two fixes, once each, though the run completed — a rutis plugin failing in `check`).
